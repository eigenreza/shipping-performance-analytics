# Power BI solution

The Power BI project is saved in the open PBIP format in `powerbi/`:

| Path | Content |
|---|---|
| `ShippingPerformance.pbip` | The project file to open in Power BI Desktop |
| `ShippingPerformance.SemanticModel/definition/` | The semantic model in TMDL (Tabular Model Definition Language), one file per table, plus relationships, roles and expressions |
| `ShippingPerformance.Report/definition/` | The report in the enhanced report format (PBIR): one folder per page, one JSON file per visual, bookmarks |
| `paginated/SegmentPerformance.rdl` | The paginated report for Power BI Report Builder, see [paginated-report.md](paginated-report.md) |
| `bpa/BPARules.json` | Microsoft's Best Practice Analyzer rules (MIT) |

A semantic model is the set of tables, relationships and measures a report is built on. DAX is the formula language of Power BI.

## How the files are made

The model and the report are generated by `spa powerbi` from a specification in `src/spa/powerbi/spec.py` (tables, friendly column names, relationships, measures with descriptions, formats and display folders, the calculation group, the field parameter, what-if parameters and roles). On Windows the generated TMDL is loaded with Microsoft's Tabular Object Model library and written back in the canonical TMDL layout, which validates it strictly. The report JSON is validated against Microsoft's published JSON schemas in the tests. Keeping the model as code means every change is reviewable in a diff, and the measure catalogue ([measures.md](measures.md)) is generated from the TMDL.

## Model design

- **Star schema, Import mode.** Four fact tables (ship-year emissions, port calls, voyage legs, daily carbon price) and four conformed dimensions (Date, Segment, Ship, Port), loaded from the gold Parquet files through one Power Query function, `GoldFile`, and one parameter, `DataFolder` (a GitHub raw URL or a local folder).
- **Relationships** are single-direction, many-to-one, on integer surrogate keys. Voyage legs relate to Port twice; the destination relationship is inactive and used by the `Legs Arriving` measure through `USERELATIONSHIP`.
- **Date table** marked as the date table, from 2018 to the data end date, with the yearly facts joined on 31 December of their year.
- **Ship** is a slowly changing dimension (see [data-model.md](data-model.md)); facts join on the version key.
- **Hidden technical columns.** Keys and raw numeric columns are hidden and not available to MDX clients; users work with measures. Implicit measures are switched off.
- **Fixed decimal** types for all numbers and only the columns the model uses are loaded.
- **Descriptions** on every table, measure and visible column; **display folders** group the measures: Emissions, Efficiency, EU ETS, Carbon Price, Carbon Rating, Ports, Voyages and Weather, Scenarios, Peers and Ranking, Data Quality, Labels.

## Calculation group: Time Intelligence

One calculation group applies time logic to any measure, so the model needs no separate "YTD" or "prior year" copies of each measure. Items: Current, Year to Date, Prior Year, Year over Year, Year over Year % (with its own percentage format), Rolling 12 Months. Pick an item in a slicer or put the "Time Calculation" column on a matrix.

## Field parameter: Metric Selector

A field parameter lets a reader choose which measure a visual shows (CO2, fuel, distance, CO2 per nautical mile, speed, CO2 in EU ETS scope, EU ETS cost, share rated D or E, CII ratio, ships reporting). The Explore page uses it with the calculation group for self-service analysis.

## What-if parameters

Speed Change, Carbon Price Scenario and Fuel Price are what-if parameters (slicers with a value measure each). A small disconnected table, Speed Relation, chooses between the speed elasticity estimated from MRV data and the engineering rule; the estimates come from the `Model Parameters` table written by the analysis.

## Row-level security

Two roles, Vehicle Carriers Only and Ro-ro Ships Only, filter the Segment and Ship tables. Both were tested in the engine by querying as a member of each role: each sees only its own segment's ships, ship-years and port calls, and the counts equal the SQL counts. Members are assigned in the Power BI service after publishing.

## Report pages

Fleet overview, Fleet efficiency, Slow steaming and carbon cost, Carbon ratings, Ports and weather, Explore, Ship profile (drill-through: right-click a ship anywhere and choose Drill through) and a ship tooltip page used by the efficiency scatter. Every page opens with three lines (What this is, How to use it, What to notice) and ends with the project footer. Three bookmarks switch the overview between all ships, vehicle carriers and ro-ro ships.

**Best Practice Analyzer.** `tools/powerbi/run_bpa.ps1` runs Tabular Editor 2 from the command line against the TMDL folder with Microsoft's rule set; results are in `results/powerbi/bpa.json`, and CI runs it on a Windows runner. A few rules conflict with deliberate design choices; those objects carry a `BestPracticeAnalyzer_IgnoreRules` annotation, and the reasons are:

| Rule | Reason for the exception |
|---|---|
| Ensure tables have relationships | Parameter, selector, measure and calculation group tables are disconnected by design |
| Reduce usage of calculated tables | What-if and field parameters are calculated tables by definition |
| Remove roles with no members | Members are assigned in the Power BI service, never in project files |
| Measure references should be unqualified | Field parameters require NAMEOF with a qualified measure reference |
| Whole numbers formatted with thousands separators | Ratios, prices and elasticities need two or three decimals |
| Remove unnecessary columns | Columns used only by report visuals or by field parameter internals |

**Reconciliation.** `spa powerbi-check` connects to the model loaded in Power BI Desktop, evaluates every measure once, compares key measures by year and segment with the same numbers computed in SQL on the warehouse, evaluates the ship-level peer measures for one ship, and queries as each security role. Results are in `results/powerbi/`.

## Performance choices

Import mode on a small star schema; integer keys; fixed decimal types; only needed columns loaded; no calculated columns; single-direction relationships; measures that filter on columns (for example `is_quality_ok`) rather than iterate rows where possible; a calculation group instead of duplicated time intelligence measures.
